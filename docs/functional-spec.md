**プロジェクト名**: JSVisualizer  
**バージョン**: 0.1 (ドラフト)  
**作成日**: 2026-05-25  
**作成者**: Tetsuo Tanaka

---

## 1. 目的・背景

### 1.1 問題

プログラミング教育において、学生はしばしば「プログラムが何をしているか理解できない」という状態に陥り、バグの修正に困難を来す。その根本原因は、**時間（CPU クロック）の経過とともに空間（メインメモリ）の内容がどのように変化するか**、すなわちプログラムの動的な振る舞いを把握できていないことにある。

既存の手段には以下の問題がある。

| 手段 | 問題点 |
|------|--------|
| 紙・静的スライド | 動作を連続的に追うことができない |
| PowerPoint アニメーション | 教材作成コストが高く、コードを変えると再作成が必要 |
| Algorithm Visualizer | 可視化専用コードの埋め込みが必要、汎用性が低い |
| Python Tutor | Python 限定、表示レイアウトが固定、JavaScript 非対応 |

### 1.2 目的

任意の JavaScript コードを貼り付けるだけで、**プログラムの実行過程を多角的に可視化**できる Web アプリケーションを提供する。

### 1.3 スコープ

- **対象言語**: JavaScript (ES6+)
- **対象ユーザー**: プログラミング入門〜中級の学習者、教員
- **対象環境**: モダン Web ブラウザ（Chrome / Firefox / Safari 最新版）

## 2. ユーザーと利用シナリオ

### 2.1 ユーザー種別

| 種別 | 説明 |
|------|------|
| **学習者** | 自分のコードの動作を確認・デバッグしたい学生 |
| **教員** | 授業でプログラムの動作を説明する教材として使いたい |
| **教材制作者** | トレース図・フローチャートのアニメーションを手軽に生成したい |

### 2.2 主要ユースケース

#### UC-01: 自作コードを可視化する
1. ユーザーはコードエディタに JavaScript コードを入力する
2. 実行ボタンを押す
3. アプリケーションは全ステップを解析し、可視化の準備を行う
4. ユーザーはステップ実行ボタンで一歩ずつプログラムの動作を追う
5. ユーザーは任意のビューに切り替えて異なる角度から動作を確認する

#### UC-02: ステップを進める・戻る
1. ユーザーはステップ粒度（式評価 / 文評価 / 関数呼び出し / 人にやさしい単位）を選ぶ
2. 進む・戻るボタン（またはキーボードショートカット）でステップを操作する
3. コード上の現在位置がハイライトされ、全可視化ビューが同期して更新される

#### UC-03: 可視化ビューを切り替える
1. ユーザーは上部のタブで表示するビューを選択する
2. 複数ビューを同時に表示してレイアウトを比較する

#### UC-04: サンプルコードを使う
1. ユーザーはサンプルセレクタから学習シナリオを選ぶ
2. コードが自動的にエディタに挿入され、すぐに可視化を開始できる

## 3. 機能要件

### 3.1 コア機能

#### F-01: コードエディタ

| 項目 | 仕様 |
|------|------|
| 入力形式 | JavaScript (ES6+) テキスト |
| シンタックスハイライト | キーワード・文字列・コメントの色分け |
| サンプルコード | プリセット選択（バブルソート、フィボナッチ、二分木 など） |
| エラー表示 | パース・実行エラーをエディタ上に表示 |

#### F-02: ステップ実行コントロール

| 操作 | キーボード | 説明 |
|------|-----------|------|
| 先頭へ | `Home` | ステップ 0 に戻る |
| 戻る | `b` / `←` | 1 ステップ前（粒度に応じた単位） |
| 進む | `n` / `→` | 1 ステップ先（粒度に応じた単位） |
| 末尾へ | `End` | 最終ステップへジャンプ |
| 粒度変更 | ドロップダウン | 式評価 / 文評価 / 関数呼び出し / 人にやさしい単位 |
| スライダー | — | trace 配列の任意位置にジャンプ |

#### F-03: ステップ粒度

| 粒度 | 内部 API | 定義 |
|------|----------|------|
| 式評価 | `stepIn()` | 全 AST ノードの enter/exit イベント |
| 文評価 | `stepOver()` | 文ノードのみ（サブ式を内部でスキップ） |
| 関数呼び出し | `stepOut()` 相当 | `CallExpression` の enter → exit |
| 人にやさしい単位 | `humanStep()` | 代入・条件判定・ループ更新・関数呼び出し等の意味ある変化点 |

---

### 3.2 可視化ビュー

#### V-01: アニメーション付きトレース表

- ステップが進むたびに表の行が追記される
- 変化した値のセルがフラッシュする（CSS transition）
- 現在の行がハイライト・スクロール追従する
- 表示する変数をユーザーが列として選択可能

**入力**: 各ステップの変数スナップショット  
**表示**: 行 = 1 ステップ、列 = 変数名

#### V-02: 静的トレース表

- 全ステップを一覧できる固定テーブル
- 変化があったステップのみを行として表示（humanStep 粒度基準）
- 現在ステップの行をハイライトしてスクロール追従

**入力**: trace-builder が生成した全ステップデータ  
**表示**: 読み取り専用の完全テーブル

#### V-03: スコープ・変数ビュー

- スコープチェーンをネストした枠で表現
- 外側から内側の順に、スコープ名と変数の一覧を表示
- 変化した変数をフラッシュ

**入力**: `ev.env[]`（スコープチェーン全体）  
**表示**: ネスト枠 + 変数一覧

#### V-04: コールスタックビュー

- スタックフレームをカード積み上げで表示
- 関数呼び出し時にカードがスライドイン
- リターン時にカードがフェードアウト
- 各フレームに関数名・現在行・ローカル変数の概要を表示

**入力**: `ev.callStack[]`  
**表示**: カードスタック（最上位が現在実行中）

#### V-05: 棒グラフアニメーション

- 指定した数値変数または数値配列を棒グラフで表示
- 値の変化を棒の高さの CSS アニメーションで表現
- ユーザーが「この変数を棒グラフで見る」と設定する変数選択 UI を持つ

**入力**: ユーザー指定変数の値の時系列  
**表示**: 棒グラフ（横軸 = 変数/添字、縦軸 = 値）

#### V-06: 色付き箱アニメーション

- 指定した配列の各要素を番号付き箱で表示
- アクセス中（オレンジ）・比較対象（青）・確定済み（緑）を色分け
- `MemberExpression` の評価を検出して対応要素をハイライト
- 変数がインデックスを指している場合、矢印で下に表示

**入力**: ユーザー指定配列の値 + アクセスされた添字情報  
**表示**: 横一列の色付き箱 + インデックス矢印

#### V-07: 変数の時系列グラフ

- 指定した変数の値の推移を折れ線グラフで表示
- 横軸 = ステップ（humanStep 粒度）、縦軸 = 値
- 複数変数を色分けして重ね描き
- 現在ステップを縦線でハイライト

**入力**: ユーザー指定変数の全ステップでの値  
**表示**: 折れ線グラフ（SVG）

#### V-08: 実行頻度ヒートマップ

- 各ソース行の実行回数を `loc.line` から集計
- 行の背景色の濃さで実行頻度を表現
- コードビュー上にオーバーレイで表示
- ホバーで実行回数のツールチップを表示

**入力**: trace 配列全体からの行ごと実行回数集計  
**表示**: コード + 背景色オーバーレイ

#### V-09: 再帰ツリービュー

- `callStack[]` を追跡して再帰呼び出しの木を構築
- 現在実行中のノードをハイライト
- exit 後、辺に戻り値をラベル表示
- ノードをクリックしてその時点の変数状態を確認可能

**入力**: trace 配列全体の callDepth・callStack 情報  
**表示**: 有向ツリー（SVG 自動レイアウト）

#### V-10: スコープ・ライフタイムタイムライン

- 縦軸 = 変数名、横軸 = ステップ数のガントチャート
- 変数の宣言〜スコープ消滅の期間をバーで表示
- スコープ別に色分け
- 現在ステップを縦線でハイライト

**入力**: 各変数の出現・消滅ステップを trace から抽出  
**表示**: ガントチャート（SVG）

#### V-11: 制御フロービュー

- if / for / while / switch を自動的にフローチャートに変換
- 現在実行中のブロックをハイライト
- 分岐でどちらのパスを通ったかを矢印の色で表示（通過済み = 青、未通過 = グレー）

**入力**: AST + trace の loc 情報  
**表示**: フローチャート（SVG）

#### V-12: メモリモデルビュー

- スタック（実行フレーム）とヒープ（オブジェクト・配列）を分離表示
- `let`/`const` 宣言でセルが生成、スコープ終了でフェードアウト
- プリミティブ値はスタックフレーム内にインライン表示
- オブジェクト・配列はヒープに分離し、矢印で参照を表現

**入力**: `ev.env[]` + 値の型情報  
**表示**: 2 ペイン（スタック / ヒープ）+ 参照矢印（SVG）

#### V-13: オブジェクトグラフ

- `env` 内のオブジェクト・配列の参照関係をノード-エッジグラフで表示
- 変更のあったノード・エッジをステップごとにハイライト
- 循環参照を矢印の向きで表現

**入力**: `ev.env[]` の全値（オブジェクト・配列を再帰的に探索）  
**表示**: ノード-エッジグラフ（SVG + 自動レイアウト）

---

### 3.3 UI 共通機能

#### F-10: コードハイライト（全ビュー共通）

- 現在実行中の行を背景色でハイライト
- 現在評価中の式（`loc` で特定）を下線でハイライト
- ステップが進むたびにスクロールして表示域に収める

#### F-11: ビュー切り替えタブ

- 上部タブでビューを切り替え
- ビュー同時表示モード（分割レイアウト）

#### F-12: 変数フォーカス設定

- 棒グラフ・色付き箱・時系列グラフの対象変数をユーザーが選択
- 選択は localStorage に保存して再訪時に復元

## 4. 非機能要件

### 4.1 パフォーマンス

| 指標 | 目標値 |
|------|--------|
| `new JSDebugger(source)` 完了（100 行以内のコード） | 500ms 以内 |
| ステップ操作のUI更新 | 50ms 以内 |
| 最大 trace 長 | 100,000 ステップ |

### 4.2 互換性

- Chrome / Firefox / Safari 最新版
- モバイルブラウザは対象外（レスポンシブ対応は Phase 5 以降に検討）

### 4.3 アクセシビリティ

- キーボードのみでステップ操作・ビュー切り替えができること
- 色分けに加えて形状・テキストでも情報を伝えること（色覚多様性対応）

### 4.4 保守性

- 各ビューが `init/update/reset/destroy` の共通インターフェースを持つこと
- ビュー追加・削除がアプリ本体のコードを変更せずできること

## 5. 用語定義

| 用語 | 定義 |
|------|------|
| TraceEvent | JSInterpreter が記録する1ステップ分の情報（phase/nodeType/loc/depth/callDepth/callStack/env/value） |
| cursor | trace 配列の現在位置を示す整数インデックス |
| humanStep | 人間が紙でトレースする際に記録する「意味のある変化点」（代入・条件判定・ループ更新・関数呼び出し等） |
| スナップショット | あるステップでの変数・スコープ・コールスタックの状態の複製 |
| diff | 前後スナップショット間で変化した変数名のセット |
| オムニシェントデバッグ | プログラムを先に最後まで実行して全ステップを記録し、後から任意のステップに移動できるデバッグ方式 |
