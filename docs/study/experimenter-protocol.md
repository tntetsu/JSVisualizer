## 事前準備チェックリスト

各セッション開始前に以下を確認する。

- [ ] ブラウザで JSVisualizer を開いてある（URL: GitHub Pages またはローカルビルド）
- [ ] ドロップダウンが「— Sample —」の状態にリセットしてある
- [ ] 設定パネルの Session Log が「● Inactive」になっている
- [ ] 参加者向け説明資料・アンケート・タスクシートが印刷済み
- [ ] タイマーを用意してある（スマートフォン可）
- [ ] 操作ログの保存先フォルダを決めてある（エクスポート後にすぐ保存できるよう）

## 進行スクリプト

### 0. 開始前（〜1 分）

> 「今日はお時間をいただきありがとうございます。JavaScript の実行を可視化するツールの評価実験に参加していただきます。全体で 60 分ほどを予定しています。」

説明資料を渡す。読んでもらう間に Session Log を準備する。

> 「研究の目的と個人情報の取り扱いについて説明資料に書いてあります。ご確認いただき、問題なければサインをお願いします。」

同意書へのサインを確認したら、**Session Log の「Start Session」をクリック**する。

---

### 1. ウォームアップ（0〜10 分）

ドロップダウンから「[Warm-up] Factorial (loop)」を選んでもらう。

> 「まず 10 分ほど、このツールの操作に慣れてもらいます。画面左にコードがあって、右に色々な表示があります。下のボタンでコードの実行を一歩ずつ追えます。特に **▷ Human** ボタン（または `h` キー）が「意味のある変化」だけに進むので使いやすいと思います。好きなタブを切り替えて探索してみてください。正解・不正解はないので、気軽に触ってみてください。」

タイマーを 10 分セット。参加者が操作している間は干渉しない（詰まっているようなら「どんな画面が見えていますか？」と声をかけて良い）。

**10 分経過 → Session Log マーカー「task1-start」をクリックしてから次へ。**

---

### 2. タスク説明（10〜15 分）

> 「ウォームアップはここで終わりです。次から 3 つのタスクをやってもらいます。各タスク約 10 分です。問題はコードのコメント（// で始まる部分）に書いてあります。分からなくても大丈夫ですので、詰まった場所を教えてください。答えは教えられませんが、見るべき画面を案内することはできます。」

> 「タスクが終わったら答えをアンケートの D 欄に書いてください。使ったビューもチェックしておいてください。」

---

### 3. Task 1（15〜25 分）

ドロップダウンから「[Task 1] Selection Sort — find the bug」を選んで Run してもらう。

> 「このコードにはバグがあります。ツールを使ってバグのある行を見つけてください。」

**タイマー 7 分セット。**

- 7 分経過して答えが出ていない or 明らかに詰まっている → [ヒント手順](#task-1-ヒント) を参照
- 完了したら → アンケート D1 記入を促し、マーカー「task1-done」をクリック、次のタスクへ

ドロップダウンから「[Task 2] Fibonacci — count function calls」を選んで Run してもらう。

**マーカー「task2-start」をクリック。**

> 「fib(4) を実行したとき、fib という関数が合計で何回呼ばれるかを数えてください。最初の fib(4) も 1 回として数えます。」

**タイマー 7 分セット。**

- 7 分経過して答えが出ていない → [ヒント手順](#task-2-ヒント) を参照
- 完了したら → アンケート D2 記入を促し、マーカー「task2-done」をクリック、次のタスクへ

**マーカー「task3-start」をクリック。**

> 「外側のループの 2 回目（i = 1）が完了した直後、配列 arr の中身がどうなっているかを答えてください。最終結果ではなく、途中の状態です。」

**タイマー 7 分セット。**

- 7 分経過して答えが出ていない → [ヒント手順](#task-3-ヒント) を参照

### 6. アンケート（45〜55 分）

アンケート用紙を渡す。

> 「お疲れ様でした。次にアンケートにご回答ください。A〜E 欄をご記入ください。10 分ほどかかります。記入中は席を外しますね。」

記入中にログを仮エクスポートしておく（JSON 推奨）。

### 7. インタビュー（55〜60 分）

アンケートを回収してから口頭で以下の 3 問を聞く。回答をアンケート F 欄にメモする。

1. 「どの可視化ビューが最も『なるほど』と感じましたか？その理由も教えてください。」
2. 「このツールを使う前後で、プログラムの動きの理解に変化はありましたか？」
3. 「授業でこのツールが使えるとしたら、どんな場面で使いたいですか？」

> 「以上で終わりです。ありがとうございました。」

**Session Log → CSV および JSON をエクスポートして保存する。**  
ファイル名に参加者 ID を付記する（例: `jsv-log-20260718-1000_P01.json`）。

## ヒント提供プロトコル

ヒントは **「使うべきビューの名前だけを伝える」** 最小限の介入とする。  
ヒントを出したら即座に Session Log マーカーをクリックすること（例: 「task1-hint」）。

### Task 1 ヒント

対象の詰まり方: `minIdx` の初期値に気づいていない、変数の変化を追えていない

> **「ExecTrace タブを開いて、各ループで `minIdx` の値がどう変化しているか確認してみてください。」**

期待される効果: ループごとに `minIdx` が `i+1` から始まっていることが表で見える。

---

### Task 2 ヒント

対象の詰まり方: 呼び出し回数を手で数えようとしている、コードハイライトのみ見ている

> **「Rec. Tree タブ（再帰ツリー）を開いてみてください。ノードが 1 つの関数呼び出しに対応しています。」**

期待される効果: ツリー全体のノード数を数えるだけで答えが出る。

---

### Task 3 ヒント

対象の詰まり方: 最終結果（全ループ完了後の値）を答えている、どこで止めるか分からない

> **「State タブで `arr` の値を見ながら、`h` キーで進めてください。`i` が 2 になった瞬間に止まると、その直前の状態が答えです。**  
> ExecTrace タブを使って `i = 1` の行を探してもいいです。」**

期待される効果: 変数パネルで `arr` がリアルタイムに更新されるのを見ながら `i = 2` に切り替わる直前で止められる。

## 正解と採点基準

### Task 1

| | |
|---|---|
| **正解** | 8 行目 `let minIdx = i + 1;` → `let minIdx = i;` に修正 |
| **バグの仕組み** | `minIdx` が `i` ではなく `i+1` から始まるため、`arr[i]` 自体が最小でも選ばれない。選択ソートは「`arr[i..n-1]` の最小値の位置」を求めるべきところ、`arr[i+1..n-1]` の最小値と `arr[i]` を交換している |
| **実際の出力** | `[1, 2, 3, 8, 5, 9]`（末尾 2 要素が未ソート） |
| **採点** | 行番号の特定 or 修正内容が正しければ正解。「minIdx の初期値がおかしい」という指摘も正解とする |

### Task 2

| | |
|---|---|
| **正解** | **9 回** |
| **呼び出しツリー** | fib(4) → fib(3) → fib(2) → fib(1), fib(0) / fib(1) / fib(2) → fib(1), fib(0) |
| **内訳** | fib(4)×1, fib(3)×1, fib(2)×2, fib(1)×3, fib(0)×2 = 合計 9 |
| **採点** | 9 回 = 正解。8 回（fib(4) を数え忘れ）は不正解。10 回以上は不正解 |

### Task 3

| | |
|---|---|
| **正解** | `[3, 1, 5, 8, 9]` |
| **導出** | i=0 完了後: [3, 5, 1, 8, 9]（swap: 5↔3, 8↔1） → i=1 完了後: [3, 1, 5, 8, 9]（swap: 5↔1） |
| **よくある誤答** | `[1, 3, 5, 8, 9]`（最終結果）→「途中の状態」と明示したが最後まで実行した |
| **採点** | `[3, 1, 5, 8, 9]` = 正解。`[3, 5, 1, 8, 9]`（i=0 完了後）は「1 回目と 2 回目を混同」として記録 |
