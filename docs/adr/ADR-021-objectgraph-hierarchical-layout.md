# ADR-021: ObjectGraph を階層型レイアウトに変更

- **決定日**: 2026-06-16
- **ステータス**: 承認済み

## 背景・課題

`ObjectGraph`（オブジェクトタブ）は当初 Fruchterman-Reingold 力学的レイアウトを採用していた。しかし以下の問題があった。

1. **無駄な空白**: 力学的レイアウトは初期配置依存で収束後も空白が残りやすい
2. **エッジ方向の不規則性**: 同じプロパティ（例: `.next`）のエッジが毎回異なる方向を向くため、データ構造の形状が直感的に読めない
3. **複数エッジの重複**: 1 ノードから 2 本以上のエッジが出る場合に重なる
4. **連結成分の重複**: 無関係なサブグラフが重なって表示される

## 決定

力学的レイアウトを廃止し、**階層型レイアウト**（左→右）に変更する。

### レイアウトアルゴリズム

```
1. hierarchicalLayout(nodes, edges)
   a. Kahn のトポロジカルソート（in-degree BFS）でソート順を決定
   b. 最長パス法: col[n] = max(col[前任者]) + 1
   c. x = col × (NODE_W + COLUMN_GAP)
   d. 同列内ノードを ROW_GAP 間隔で上から配置

2. layoutGraph(nodes, edges)
   a. 無向 BFS で連結成分を検出
   b. 各成分を hierarchicalLayout() で独立配置
   c. yOffset を成分ごとに COMP_GAP ずつ増加（縦積み上げ）
   d. 成分 ≥2 のとき点線境界矩形 .og-comp-bg を描画
```

### エッジ描画

- **肘型コネクタ**: `M x1,y1 H mx V y2 H x2`（出口右→縦→入口右）
- **ポートスプレッド**: 同一ノードから N 本のエッジが出る場合、出口 y を `ny + (i+1)*h/(n+1)` で均等分散（`srcPort`/`dstPort` Map で管理）。これによりラベル・エッジの重複を回避
- **ラベル配置**: 縦セグメント左側（`x = mx - 2, text-anchor = 'end'`）に 8 文字以上表示できる間隔（COLUMN_GAP=80px）を確保

### ノード

- サイズ: NODE_W=110 / NODE_H_MIN=32 / ROW_H=13 / MAX_PROPS=8
- 背景色: 6 色パレット（`--og-bg-0` ～ `--og-bg-5`）でノード順に割り当て

## 根拠

- **同じプロパティが同じ方向**: 階層型は「参照先は常に右」という規則性を保持でき、連結リスト・ツリー・グラフ構造の形状が一目でわかる
- **空白の最小化**: 列幅固定・行積み上げで無駄な空白が出にくい
- **連結成分の独立性**: 無関係なオブジェクト群（例: `list` と別の変数）が重ならない

## 結果・影響

- `forceDirectedLayout()` 関数を削除
- `hierarchicalLayout()` / `layoutGraph()` を追加
- CSS に `--og-bg-0` ～ `--og-bg-5` と `.og-comp-bg` を追加
- `.og-rect` の `fill` を inline style（`NODE_BG[ni % 6]`）で設定するため CSS 側の `fill: var(--surface)` を削除
- 非 DAG（循環参照を含むグラフ）では Kahn ソートが完全ではないが、実用上はほぼ DAG であり問題ない
