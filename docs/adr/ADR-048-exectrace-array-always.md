# ADR-048: 実行トレースの「配列」列で、ポインタが無くても配列を描く

## ステータス

採択済み（2026-11-02）。[ADR-037](ADR-037-exectrace-array-pointer-overlay.md) の「ポインタが検出された配列のみ描く」は本来の意図と違っていたため、意図どおりに直す。

## コンテキスト

ADR-037 で「配列」列を設計したときの意図は、「添字に使われている変数が見つかったら、その変数の値を配列の添字とみなしてラベルを描く」ことだった。添字の変数が見つかった配列だけを表示する、という意図はなかった。

ところが実装と ADR-037 の記述は「そのステップでポインタが 1 つ以上検出された配列のみ描く」になっていた（`detectPointerVars()` の結果が空ならミニ図を描かない）。ポインタは「ソース中で `arr[i]` の形で添字に使われ、値が `[0, arr.length)` の整数である変数」として検出する。

そのため、次のように添字がリテラルだけのプログラムでは、ポインタが 1 つも見つからず、「配列」列がすべての行で空になっていた。

```js
const table = [];
table[0] = 54;
table[1] = 12;
table[3] = 25;
table[4] = 36;
table[10] = 43;
```

一方、`let i = 0; table[i] = 54;` のように添字に変数を 1 回でも使うと、`i` がポインタとして検出され、以降の行では（`i` を使っていない行でも）表示された。利用者からは「添え字が変数の行以降だけ表示される」不具合に見える。

配列タブ（V-07、`color-box/index.js`）は、意図どおりポインタの有無に関係なく選んだ配列を描き、ポインタがあればラベルを付けている。

## 決定

本来の意図どおり、配列タブと同じく、各行でその行のスコープにある配列（`envMap.has(arrName)`）をすべて描く。ポインタが検出されれば、従来どおりその位置にラベルを付ける。

## 結果

- 添字がリテラルだけのプログラムでも、各行の配列の中身が見える
- ADR-037 の該当箇所に、この ADR で直した旨の注記を入れた
- ポインタを使うプログラム（選択ソート等）では、配列を作った行やループに入る前の行にも図が出る。ポインタ位置の比較（ADR-037 の狙い）はこれまでどおりできる
- 複数の配列を使うプログラムでは、スコープにある配列がすべて並ぶ。表示枠は横スクロールでき、幅はドラッグで変えられる（ADR-037）

## 代替案

- **前の行から作られた・書き換わった配列だけ追加で描く**: 不採用。読むだけの行（`const x = table[3];`）で図が消え、行によって出たり消えたりする。配列タブの表示とも揃わない
- **リテラルの添字もポインタとして扱う**（`table[3]` の 3 を強調する）: 不採用。ソース上の位置と行の対応付けが必要になり、ポインタ行に変数名ではない数字が並んで「ポインタ」の意味が変わる
