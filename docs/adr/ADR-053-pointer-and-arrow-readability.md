# ADR-053: 範囲の端の変数に印を付け、メモリ・オブジェクトの矢印をノードの上を通らないように描く

## ステータス

採択済み（2026-11-16）

## コンテキスト

連載記事の第 8〜12 回の下書きで、次の 3 つが読みにくかった。

1. **配列・実行トレース**: 二分探索の `lo`・`hi` に印が付かない。印の対象は `a[mid]` のように添字の先頭に書かれた変数だけで、範囲の両端を表す変数が図に出ない
2. **メモリ**: STACK と HEAP は左右に並ぶのに、矢印は HEAP の見出しの上下から入る。そのため、矢印が途中のヒープ要素のマスや、ほかのフレームの上を横切る
3. **オブジェクト**: 右から左へ戻る矢印（双方向リストの `prev`、循環リストの最後から先頭）と自己参照の矢印が、ノードの中を突き抜ける。自己参照はほとんど見えない。輪のある構造では、トポロジカルソートが途中で止まるので、配置も崩れる

## 決定

### 1. 印の対象を広げる（`computeSubscriptVars`）

従来の「添字の先頭の識別子」に、次の 2 つを加える。

- 足し算・引き算だけでできた添字の中の識別子（`a[n - 1 - i]` の `i`、`grid[i][j]` の `j`）
- 添字の変数と **互いに** 計算し合う変数。`mid = Math.floor((lo + hi) / 2)`（添字の変数の右辺に出てくる）と `lo = mid + 1`（自分の右辺に添字の変数が出てくる）の両方を満たすもの

片方だけの変数（`idx = key % size` の `key` など）は、範囲の端とはいえないので含めない。値が `[0, 配列の長さ)` に入るときだけ印を付ける条件は変えない。

### 2. メモリの矢印は、左右に離れているときは横から入れる

始点（`→ #0`）が終点（`#0` の見出し）より左に離れているときは、自分の行の高さのまま右へ進み、STACK と HEAP のあいだでだけ曲げて、見出しの左端へ入れる。同じ対象に集まる矢印は、見出しの高さの中で終点を分ける。HEAP の中どうし（入れ子の配列など）や、狭い画面で上下に並ぶときは、従来どおり上下から入れる。

### 3. オブジェクトの輪を作る矢印は、ノードの外を通す

- 配置: 深さ優先探索で、輪を作るエッジ（後退辺・自己参照）を求め、それを除いた DAG で従来どおり Kahn のトポロジカルソートと最長パス法で列を決める
- 後ろ向きの矢印: 右へ出て、連結成分のノード群の下を回り込み、宛先の左辺へ入る。回り込み線は 1 本ずつ 8px ずつ下にずらし、その分の高さを成分に確保する
- 自己参照: ノードの右に小さな輪を描いて、右辺へ戻す

## 影響（デグレードの確認）

組み込みのサンプル 21 本、記事の題材、追加の題材（挿入ソート、両端から入れ替える反転、配列と数を混ぜた集計、双方向リスト、循環リスト、自己参照、配列とオブジェクトの混在）で、修正の前後の画面を画素単位で比べた。

- 配列・実行トレース: 変わったのは二分探索（`lo`・`hi` が付く）とクイックソート（範囲の左端 `lo` が付く）だけ。ほかの 12 本は同じ
- オブジェクト: 輪のない構造（木・連結リスト・クラス・入れ子の配列）では後退辺がないので、配置も矢印も同じ。変わったのは輪のある 4 本だけ
- メモリ: STACK から HEAP への矢印はすべて横から入る形に変わる（意図した変更）。HEAP の中どうしの矢印は同じ

## 検討した案

- 印の対象に、添字の変数の右辺に出てくる変数をすべて含める: ハッシュの `key` のように、範囲の端ではない変数にも印が付くので採らなかった
- メモリの矢印を、ヒープ要素の箱全体の左辺へ入れる: 見出しへ入れる従来の考え方（どの番号の実体かを指す）を保つため、見出しの高さの中に入れた
- オブジェクトの後ろ向きの矢印をノードの上を回す: 一番上のノードの上には変数名のラベルがあるので、下を回すことにした
