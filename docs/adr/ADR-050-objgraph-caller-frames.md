# ADR-050: オブジェクトビューに呼び出し元のオブジェクトを表示し、関数と宣言前の変数の表示を直す

## ステータス

採択済み（2026-11-04）

## コンテキスト

ADR-049 で、コールスタックとメモリのビューは呼び出し元の変数を表示するようになった。オブジェクトビューは「いま見えている変数」（`state.variables`）だけを起点に描くので、関数の実行中は呼び出し元だけが持つ配列やオブジェクトが図から消えていた。

あわせて、次の表示の問題が残っていた。

- メモリビューで、関数とクラスの値が `[object Object]` と表示される。ヒープに載せない値として `fmtPrim()` に渡されるが、`fmtPrim()` が関数を想定していなかった
- オブジェクトビューで、宣言前の変数が `Symbol(TDZ)` と表示される（ADR-038 の漏れ）

## 決定

- **オブジェクトビュー**: `buildGraph()` に `callStack`・`frameEnvs`・`globalBlockVars` を渡し、呼び出し元のフレームが持つ配列・オブジェクトも描く
  - 同じ名前の変数が複数のフレームにあるので、`a (main)` のようにフレーム名を付ける。グローバルのブロックの変数は `t (global)`
  - JSInterpreter が同じ値を同じ複製で記録するので（ADR-049）、共有している配列は 1 つのノードになり、`list, a (main)` のように変数名が並ぶ
  - 数値などのプリミティブは足さない。呼び出しが深いと図が読みにくくなるため。呼び出し元のプリミティブはコールスタックビューで見られる
  - いま見えている変数と同じ名前で同じ値のもの（クロージャなど）は重ねて足さない
- **メモリビュー**: `fmtPrim()` で関数を `ƒ 名前`、クラスを `class 名前`、組み込み関数を `[native]` と表示する（`formatValue()` と同じ）
- **オブジェクトビュー**: `fmtVal()` で宣言前の変数を「—」、プロパティの関数を `ƒ 名前`、クラスを `class 名前` と表示する

## 結果

- 関数の実行中も、配列やオブジェクトが図から消えない。関数に渡した配列を呼び出し元と共有していることが図でわかる
- 再帰が深いと、ノードとラベルが増える。フレーム名は関数名だけなので、同じ関数の別の呼び出しはラベルでは区別できない（ノードは別々に描かれる）

## 代替案

- **ラベルに引数も入れる（`a (main(3))`）**: 不採用。ノードの幅を超えて読みにくくなる
- **呼び出し元のプリミティブも描く**: 不採用（上記）
