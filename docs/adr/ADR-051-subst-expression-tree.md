# ADR-051: 置換ビューを式の木で管理し、引数の中の呼び出しを正しく展開する

## ステータス

採択済み（2026-11-04）

## コンテキスト

置換ビューは式を文字列で持ち、`return` のたびに呼び出しの文字列（`f(2)` など）を `indexOf` で探して置き換えていた。そのため、次の問題があった。

- 再帰呼び出しが別の関数の引数になると、外側の呼び出しが式から消える。`return twice(f(n - 1));` が `f(2)` と表示され、`f(3) → f(2) → f(1) → f(0) → 1 → 8` のように式と結果が合わなかった。`getCallFrame()` が「最初に深くなったフレーム」を返すので、引数の中の呼び出しのフレームを外側の呼び出しのものと取り違えていた
- 同じ見た目の呼び出しが 2 つあると、位置で区別できない
- 終了条件のない再帰では呼び出しの exit がないので、`2 * power(x, n - 1)` のまま止まっていた
- `2 * f(1)` の `f(1)` を `n + 1` に置き換えると `2 * 1 + 1` になり、計算の順番が変わって見えた

## 決定

- 式を「文字列と呼び出しノードの配列」の木で持つ。呼び出しノードは CallExpression enter の trace 位置と結びつけ、`return` では実行中の呼び出し（`open` の先頭）のノードを置き換える
- 別の関数の引数になった呼び出しは、外側の呼び出しの子ノードにする。外側の関数に入った時点で（＝引数の値が決まった時点で）、外側のノードを `twice(2)` のように引数の値で書き直す行を足す
- ユーザー定義関数かどうかは callee の評価結果で判定する。ネイティブ関数の呼び出しは中へ進み、引数の変数を値に置き換える
- フレームは呼び出しの exit の直前のイベントから取る。exit がないときは最初に深くなったイベントから取り、ソースの範囲は enter の `end` を使う
- 置き換えで計算の順番が変わるときは括弧を付ける。`+` どうし・`*` どうしは括弧を付けない（`2 * 2 * 2` はこれまでどおり）

## 結果

- `fastPower` のような引数の中の再帰も、式と結果が合う形で見られる
- 終了条件のない再帰は、止まるまで値で展開される
- `hasContent()` は全行を作らず、ユーザー定義関数の呼び出しがあるかだけを見る

## 代替案

- 文字列のまま外側の呼び出しを残す: 引数が式のままだと次の `return` で呼び出しの文字列が見つからず、展開が止まる
- AST から式を組み立て直す: 正確だが、利用者が書いた空白や括弧が表示から失われる
