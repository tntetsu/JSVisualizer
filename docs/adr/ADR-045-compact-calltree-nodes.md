# ADR-045: 呼び出しツリーのノードをコンパクトにする（引数を関数名の隣に書く）

## ステータス

採択済み（2026-10-19）

## コンテキスト

呼び出しツリー（V-10b、CallTree）のノードは、RecursionTree と同じ表示形式（ADR-027）で、幅 160px・高さ 80px の固定サイズだった。1行目に関数名、2行目（長ければ3行目も）に引数、その下に戻り値、左下に cost を書いていた。

`fib(5)` のような短い呼び出しでは四角の中の大部分が空白になり、ノード間の間隔（横 20px・縦 52px）も広いため、少し深い再帰でもツリーが画面に収まらなかった。また、関数名と引数が別の行に分かれていると、コードに書かれている `fib(5)` という呼び出しの形と見た目が対応しない。

## 決定

ノードを次の2行のコンパクトな表示に変える（`src/views/call-tree/index.js`）。

- **1行目**: `fib(5)` のように関数名と引数を並べて1行で書く（関数名は太字の `ct-name`、引数は `ct-args` の `<tspan>`）。右端に状態アイコン（…/▶/✓）
- **2行目**: 左に `cost:N`、右に戻り値 `→ 値`（完了後に表示）
- **ノード幅は可変**: 1行目と2行目の文字数から描画幅を見積もり（モノスペースで半角 0.6em・全角 1em）、長い方に左右 6px の余白を足す。戻り値は `init()` 時点で分かっているので、完了後に出る戻り値の幅も最初から含め、表示中に幅が変わらないようにする
- **高さ・間隔を詰める**: NODE_H 80→34、横の間隔 20→12、縦の間隔 52→28、外側の余白 24→12
- サブツリー幅は `max(ノード幅, 子の幅の和＋gap)` とし、ノードの方が広いときは子の並びを中央に寄せる

引数が長い場合の2行への折り返し（`fmtArgsLines()`）はやめた。個々の値は `fmtArg()` で切り詰められる（配列は先頭4要素まで）ので、1行でも極端に長くはならない。

## 結果

- 短い呼び出しのノードは四角の中の空白がほとんどなくなり、同じ大きさの画面により深いツリーが収まるようになった
- 非アクティブの RecursionTree（`recursion-tree/`）は従来の表示形式のまま残した。ADR-027 で統合した「表示形式」のうち、cost の計算とレイアウトアルゴリズムは引き続き共通
- 文字幅は見積もりなので、フォントによっては数 px の余白の差が出る。描画後に `getComputedTextLength()` で測る方式は、レイアウト前に幅が必要なため採らなかった

## 代替案

- **固定幅のまま余白だけ減らす**: 不採用。引数の長さが呼び出しごとに大きく違う（`fib(1)` と `mergeSort([5, 3, 8, 1, …])`）ため、最長に合わせると短いノードが空白だらけになる
- **引数が長いときだけ2行に折り返す**: 不採用。関数名と引数が離れる場合とそうでない場合が混在し、かえって読みにくい
