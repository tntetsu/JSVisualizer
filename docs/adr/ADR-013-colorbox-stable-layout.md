# ADR-013: ColorBox の 2 パス走査による安定レイアウト

- **決定日**: 2026-06-04
- **作成日**: 2026-06-14
- **ステータス**: 承認済み（commit `42c901f`、v1.2 設計ドキュメント）

## 背景・課題

配列ビュー（ColorBox）では、ステップが進むにつれて配列の長さやポインタ変数の数が変化する。これを素朴に実装すると、ステップ更新のたびにグリッドの高さ・幅が変化し、レイアウトが「飛び跳ねる」問題が生じた。特に複数配列を同時表示する場合、各配列ブロックのサイズが不揃いに変化してしまった。

## 決定

`#scanTrace()` を 2 パスで実装する。

**第 1 パス**: 各配列の `maxWidth`（最大グリッド幅）と `maxGridHeight`（最大グリッド高さ）をトレース全体から事前計算する。

```js
// 第1パス: 全 humanStep を走査して最大サイズを計算
m.maxWidth      = Math.max(m.maxWidth,      len * CELL);
m.maxGridHeight = Math.max(m.maxGridHeight, IDX_H + CELL + ptrCount * PTR_H);
```

**第 2 パス**（通常の renderLoop）: `#render()` で `.cb-grid` に `min-width` / `min-height` を固定値として設定し、配列長やポインタ数が変化しても領域が動かないようにする。

空配列時（`arr.length === 0`）も同じ `min-width`/`min-height` を設定し、「配列が空です」メッセージを内包することで占有領域を確保する。

## 根拠

- `min-width` / `min-height` を最大値で固定することで、ステップ間でグリッドサイズが変化せず、ユーザーの目が「ジャンプ」しない
- 事前計算は `init()` 時に 1 回だけ行い（`TraceBuilder` のキャッシュと同じ思想）、`update()` は高速に動作する

## 結果・影響

- `ColorBox` の `init()` が以前より重くなった（全 humanStep を 2 回走査）が、TraceBuilder キャッシュの恩恵で実際には許容範囲内
- 空配列の表示が安定し、配列が初期化されてから要素が入るまでの変化を視覚的に追えるようになった
