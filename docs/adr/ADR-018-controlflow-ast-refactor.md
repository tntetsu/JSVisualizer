# ADR-018: 制御フロービューの AST ベース構造的フローチャートへの刷新

- **決定日**: 2026-06-04
- **作成日**: 2026-06-15
- **ステータス**: 承認済み（commit `f5e86a9`）

## 背景・課題

Phase 4（commit `754fd72`）で実装した初期の制御フロービューは、`TraceBuilder.buildControlFlow()` が返す humanStep の **行番号遷移**（`lineNo → lineNo`）を元にノード・エッジを構築していた。しかしこのアプローチには以下の問題があった。

- 同一行に複数の制御構造がある場合、ノードが重複または欠落する
- ループの「戻りエッジ」と「前向きエッジ」の区別が行番号の大小比較に依存するため、入れ子ループで誤判定が頻発した
- フローチャートとして「if/else の分岐」「while の条件-本体-戻り」といった構造が表現されず、単なる実行順のグラフになっていた

## 決定

制御フロービューを **AST ベースの構造的フローチャート**に刷新する（commit `f5e86a9`）。

### レイアウト規則

- ノードはソースの **first-seen 順**に縦並びで配置する（実行回数ではなく出現順）
- **前向きエッジ**（行番号が増加する方向）は**右側**に描画
- **後向きエッジ**（ループ折り返し）は**左側**に描画し、破線（`stroke-dasharray: 6 3`）＋オレンジ色で色覚多様性対応

### `buildControlFlow()` の出力

```js
{
  nodes: [{ id, line, snippet }, ...],   // first-seen 順
  edges: [{ from, to, back }, ...],      // back=true が後向きエッジ
  humanSteps: number[],                  // カーソル位置の更新に使用
}
```

### `update()` の方針

アクティブノード（現在 humanStep の行に対応するノード）の CSS クラス `cf-node--active` を付け替えるのみ。SVG を再描画しない。

## 根拠

- AST 構造に基づくフローチャートは「if の分岐」「while のループバック」を自然に表現でき、教育用として意味が通る
- first-seen 縦並びにより、ソースコードの読み進める方向とフローチャートの上下方向が対応する
- 後向きエッジを左に分離することで、前向きエッジとの視覚的干渉が減る

## 結果・影響

- `TraceBuilder.buildControlFlow()` の出力仕様が変更された（`humanSteps` フィールドの追加、`nodes` の順序が実行順→ first-seen 順に変更）
- `control-flow/index.js` の `init()` で SVG を一括生成し、`update()` はクラス付け替えのみという「静的生成＋属性更新」パターン（ADR-006 参照）に統一された
- 初期実装（Phase 4）の `buildControlFlow()` に依存していたコードは刷新後の出力形式に合わせて更新が必要だった
