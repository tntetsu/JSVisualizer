# ADR-046: 表示言語の初期値をブラウザの言語から決め、エラーメッセージも英語表示にする

## ステータス

採択済み（2026-10-30）

## コンテキスト

表示言語（ADR-025）は `localStorage('jsv-lang')` に保存された値を使い、保存された値がなければ日本語にしていた。英語圏の読者向けの記事（連載の英語版）から `?code=` のリンクで JSVisualizer を開くと、最初は日本語の画面になり、右上の EN ボタンで切り替えてもらう必要があった。

また、エラーメッセージはローカライズの対象外だった。JSInterpreter のエラーメッセージ（`未定義の変数: 'i'` など）と、URL クエリでの読み込みに失敗したときのメッセージ（`src/core/exercise-source.js`）は日本語で作られるため、英語表示にしてもエラーの本文だけは日本語のままだった。

## 決定

### 1. 表示言語の初期値

保存された設定がないときは、ブラウザの優先言語（`navigator.languages` の先頭、なければ `navigator.language`）が日本語（`ja`、`ja-JP` など）なら日本語、それ以外なら英語で表示する（`i18n.js` の `detectLang()`）。

- 保存された設定があれば、従来どおりそれを優先する
- 自動で決めた言語は保存しない。EN ／ 日 ボタンで切り替えたときだけ保存する（ブラウザの言語設定を変えたら、それに従うようにするため）
- 言語の情報が取れないときは、従来どおり日本語にする

### 2. エラーメッセージの英語化

英語表示のときは、エラーメッセージの本文を英語に置き換えて表示する（`src/utils/error-message.js` の `localizeErrorMessage()`）。

- JSInterpreter は変更しない。JSInterpreter は日本語のメッセージを作り続け、JSVisualizer が表示する段階で既知の文型（正規表現）を英訳する
- 先頭の `[Parser] 5:10: ` ・ `[Lexer] 3:2: ` ・ `[Runtime] 7:4: ` は残し、本文だけを置き換える
- 文型にあてはまらない本文（利用者が `throw` したメッセージなど）は、そのまま表示する
- 翻訳は `CodeEditor.showError()` の中で行う。翻訳前のメッセージを覚えておき、表示中に言語を切り替えたら訳し直す（カーソルは動かさない）
- 利用ログ（`session-logger.js` の `errorMessage`）には、従来どおり翻訳前の日本語のメッセージを記録する。分析するデータの形を、表示言語によって変えないため

JSInterpreter 側でメッセージを増やしたり変えたりしたときに英訳の漏れに気づけるよう、`tests/utils/error-message.test.js` が `../JSInterpreter/src` のソースからエラーメッセージ（`Error(` ・ `consume(` の行にある日本語の文字列）を集め、すべて英訳されることを確かめる。

## 結果

- 英語のブラウザで初めて開いた人は、最初から英語の画面で使える。日本語のブラウザで使っている人（授業の受講者の大部分）の表示は変わらない
- ブラウザの言語を英語にしている日本の利用者は、初めて開いたときに英語の画面になる。EN ／ 日 ボタンで一度切り替えれば、以後はその設定が保存される
- エラーの本文も英語になった。英語表示で日本語が残るのは、主にサンプルプログラム名（とそのコード中のコメント）になる
- JSInterpreter のメッセージの文言を変えると英訳が外れることがある。その場合はテストが失敗するので、`error-message.js` の文型を直す

## 代替案

- **JSInterpreter にエラーコードと英語のメッセージを持たせる**: 不採用。JSInterpreter の API と、それを使う他のプロジェクトに影響する。表示の言語は JSVisualizer の関心事なので、JSVisualizer の中で閉じる方が影響が小さい
- **URL クエリ `?lang=en` で言語を指定する**: 今回は採らなかった。ブラウザの言語で決めれば、リンクを作る側が言語を意識しなくてよい。必要になれば、ブラウザの言語より優先するクエリとして追加できる
- **自動で決めた言語も保存する**: 不採用。ブラウザの言語設定を後から変えても追従しなくなる
