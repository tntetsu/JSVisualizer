# ADR-056: C のメモリの見せ方 — ポインタの矢印・フレームの中の箱（言語プロファイルの省略できる関数）

- ステータス: 採用（作業ブランチ `feature/multilang`。CppVisualizer の Phase 1）
- 日付: 2026-11-26

## 背景

CppVisualizer（C・C++ 版）は、このフロントエンドを言語プロファイル（ADR-055）で使う。C のポインタは「アドレス」という 1 つの値で、配列の要素・構造体のフィールド・ほかの変数を指す。また、関数の中の配列・構造体はスタック（フレームの中）にあり、2 次元配列の行や構造体の中の配列は、外の箱の中に値として入っている。

メモリ・オブジェクトのビューは JS の値の形（オブジェクト・配列はヒープにあり、変数はそれを参照する）を前提にしていて、C のポインタを箱として描くと、2 段の矢印になり、指す要素も分からなかった（CppVisualizer の phase0-report.md 3.3 節）。

## 決定

言語プロファイルの `valueModel` に、**省略できる関数を 4 つ**足す。持たない言語（JS・Python・Java）では、ビューの HTML は変わらない。

| 関数 | 意味 | 使うビュー |
|---|---|---|
| `pointer(v)` | 値が「場所を指す」値なら、指す先を返す：`{ target: 箱, key: 添字・キー }`（箱の中のマス。`key: null` なら箱の全体）か `{ variable: 名前, frame: 呼び出しの番号 \| null }`（変数）。そうでなければ `null` | メモリ（矢印）、オブジェクト（辺・タブの有効化） |
| `inFrame(v)` | 変数の値の箱を、ヒープでなく、その変数のフレームの中に描くか | メモリ |
| `embedded(v)` | 箱の中の箱を、別の箱にせず、外の箱のマスの中に描くか | メモリ |
| `stale(v)` | 解放した・スコープが終わった箱か（点線で薄く描く） | メモリ |

メモリのビュー（`views/memory-view/index.js`）：

- `pointer` があるとき（`cMemory()`）だけ、新しい描き方にする。変数の行に `data-var="呼び出しの番号|名前"`（グローバルは `global|名前`）、箱のマスに `data-cell-key` を付け、ポインタの行・マスに `data-ref-cell="箱の番号|キー"`・`data-ref-var`・`data-ref-heap`（箱の全体）を付ける。矢印は、これらの印から終点の要素を探して描く（`#arrowTarget`）。ポインタの値は `→ #1` でなく、言語プロファイルの書き方（`&a[2]`）
- `buildHeap` は、ポインタが指す箱もヒープの一覧に入れる（ポインタ自身は箱にしない）
- `inFrame` の箱はフレームの中の変数の行に、`embedded` の箱は外の箱のマスの中に描き（`.mv-inline-box`）、ヒープの側には出さない。`stale` の箱は `.mv-heap-obj--stale`
- テストのため `buildHeap` を公開した

オブジェクトのビュー（`views/object-graph/index.js`）：`pointer` の `target` を辺の先にする（変数・箱のマス）。ポインタだけを持つプログラム（連結リストの `head`）でもタブを有効にする（`hasContent`）。

## 例とテスト

C 版で見える変化の例は CppVisualizer の ADR-005 にある（`p = &a[2]` で、p から a の 2 番のマスへ矢印など）。

- `tests/utils/language-hooks.test.js`：JS のプロファイルは持たないこと、C のような値の見せ方で、ポインタの指す箱がヒープに載ること・オブジェクトのビューの辺になること
- **JS 版の表示は変わらない**：組み込みサンプル 21 本と記事の題材 29 本で、5 つのステップ位置 × 全タブの `#view-container` の HTML・コンソール・ステップ数・エラー表示を、変更前のビルド（88da21c）と比べた（PyVisualizer の `scripts/capture-js-dom.mjs`）。結果は下の追記
- Python 版（PyVisualizer のテスト 387 件）・Java 版（JavaVisualizer のテスト 466 件）もすべて通る。Java 版の全サンプル × 全タブの表示も、変更前と変更後の JSVisualizer でビルドして比べた（結果は下の追記）

## 追記（2026-11-27）：変わらないことの確認の結果

- JS 版：組み込みサンプル 21 本・記事の題材 29 本 × 5 時点 × 全タブ、3,050 件が、変更前（88da21c）のビルドとすべて一致（タブを切り替えて 600 ms 待って記録）
- Python 版：全サンプル 27 本・1,917 件、Java 版：全サンプル 30 本・2,130 件が、変更前と変更後の JSVisualizer でビルドしたサイトどうしで、すべて一致（JavaVisualizer の `capture-dom.mjs` の記録と正規化）
