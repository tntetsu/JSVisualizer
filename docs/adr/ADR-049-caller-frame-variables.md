# ADR-049: 呼び出し元のフレームに、呼び出した地点から見える変数をすべて表示する

## ステータス

採択済み（2026-11-04）

## コンテキスト

連載記事（第 3 回）の題材を確かめていて、関数の実行中に呼び出し元のフレームから変数が消えることがわかった。

```javascript
function inner(x) { return x * 2; }
function outer(a) {
  let result = a;
  for (let i = 0; i < 2; i++) {
    result = result + inner(i);   // inner の実行中、outer の枠には a しか出ない
  }
  return result;
}
```

`TraceEvent.frameEnvs` は各フレームの `callEnv` のスナップショットだった。関数本体の `let`／`const` は `callEnv` の内側のブロックの環境に入るので、記録されるのは引数と `var` だけだった。グローバルの `for` の中から関数を呼んだときも、ブロックの変数（`i` など）が Global のフレームから消えていた。実行中の関数の変数は `scopes` から表示するので、問題は呼び出し元のフレームだけに出ていた。

また、スナップショットごとに値を別々に複製していたので、呼び出し元と呼び出し先が同じ配列を指していても、スナップショットの上では別の物だった。メモリビューのヒープは `scopes` だけから作っていたため、呼び出し元だけが持つ配列は `→ #?` と表示された。

## 決定

### JSInterpreter（JSInterpreter の ADR-013）

- `frameEnvs[i]` に、フレーム i が次のフレームを呼び出した地点から見える変数（引数、関数本体やブロックの let/const/var）を記録する。内側の同名の変数を優先する
- `TraceEvent.globalBlockVars` を追加する。関数の呼び出し中に、グローバルのブロックにある変数を記録する
- 1 つの TraceEvent の `env`・`frameEnvs`・`globalBlockVars` で、複製の対応表を共有する。同じ配列やオブジェクトを指す変数は、同じ複製を指す

### JSVisualizer

- `mergeScopesForDisplay()` に `globalBlockVars` を渡し、Global のフレームに合わせて表示する（コールスタック・メモリ・ライフタイム、非アクティブのスコープビュー）
- メモリビューのヒープを、`scopes` に加えて `frameEnvs`・`globalBlockVars` からも作る。複製が共有されるので、共有している配列は 1 つのヒープ要素になり、呼び出し元と呼び出し先の両方から矢印が伸びる
- メモリビューの値の表示（`fmtPrim`）に TDZ の扱いを足す。宣言の途中で関数を呼ぶと呼び出し元に未初期化の変数が現れるため、`Symbol(TDZ)` ではなく「—」と表示する（ADR-038 の漏れ）

## 結果

- 関数を呼んでも、呼び出し元の変数は枠に残り、現在の値が見える。「呼び出すと変数が消える」という誤解を招かない
- 配列を関数に渡したとき、メモリビューで参照の共有が正しく見える
- 記録する変数が増えるので、実行前の解析は重くなる。再帰の深い 4 万 8 千ステップのコードで 650ms → 860ms

## 代替案

- **関数本体のブロックの環境だけを記録に足す**: 不採用。ループの中で関数を呼ぶと `i` が消える症状が残る。ループからの呼び出しは入門者のコードに多い
- **関数本体を `callEnv` で直接評価する**: 不採用。`function f(x) { let x; }` の扱いが変わるなど、言語の動作に影響する。表示の問題は記録の側で直す
