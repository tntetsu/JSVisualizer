# ADR-040: BhvVisualizer埋め込み時は設定パネルの評価実験用UIを取り除く（`# BHV:` タグ）

## ステータス

採択済み（2026-09-28）

## コンテキスト

設定パネル（⚙）には、テーマ切り替えの下にCELDA 2026評価実験向けのUI（`# STUDY:`、ADR-024）が
常に表示されている。「Session Log」の状態表示・`Start Session`ボタン・ワンクリックマーカー
（「T1 開始」等）・自由マーカー・JSON/CSVダウンロードで、いずれも**実験者が手動で操作する**前提のものである。

BhvVisualizer（別リポジトリ）に`<iframe>`埋め込みされたときも、このUIはそのまま学習者に見えていた。
これには次の問題がある。

- 学習者には意味が分からず、授業で配布する学生向けマニュアル（学習者にはJSVisualizerの存在を
  意識させない方針）では説明もしていないため、混乱の元になる
- ADR-028の`init`ハンドシェイク後は`sessionLogger`の記録がそのまま親ウィンドウへ送られるため、
  学習者がマーカーボタンを押すと、BhvVisualizerの操作ログに学習とは無関係な`marker`イベントが紛れ込む
  （BhvVisualizerのログ仕様では`marker`は「当面は不使用」）

## 決定

BhvVisualizerから`init`ハンドシェイクを受け取った時点で、評価実験用UIを設定パネルから取り除く。

- `web/index.html`の`<!-- STUDY MODE -->`ブロック内に、区切り線と「Session Log」セクションを包む
  `<div id="study-mode-section">`を追加
- `src/app.js`の`init`受理処理（`# BHV:`）の末尾で`document.getElementById('study-mode-section')?.remove()`
  を呼ぶ。テーマ設定セクションは残す

`init`を受け取った場合にのみ動く配線のため、ADR-028と同じく`# BHV:`タグで隔離する。スタンドアロン起動・
公開デモ・`init`を送らない他の埋め込み利用者では従来通り表示される。

`hidden`属性で隠すのではなく要素ごと取り除くのは、`init`受理後にこのUIを再表示する経路がなく、
残しておく理由がないため。`study-panel.js`は取り除いた要素への参照を持ち続けるが、DOMから外れた要素の
表示を更新するだけで副作用はない。

## 検討した代替案

- **iframe内で動いているか（`window.top !== window`）で判定して隠す**: `init`を送らない他の埋め込み利用者
  （実験者が別ページに埋め込んで使う場合など）からもUIが消えてしまう。BhvVisualizer固有の事情なので、
  BhvVisualizerからの明示的な要求（`init`）を条件にする方が影響範囲が狭い
- **URLクエリで表示/非表示を指定する**: 汎用機能として加えるほどの需要がなく、BhvVisualizerは既に
  `init`を必ず送っているため、新たなパラメータを増やす必要がない
- **`# STUDY:`ブロック自体を削除する**: 評価実験（CELDA 2026）のUIはスタンドアロンでは引き続き使うため、
  削除はしない（ADR-024の削除手順は実験終了後に適用する）

## 安全性の担保

- `verify-bhv-hook.mjs`のテストCに3件追加（計16件合格）
  - `init`受理前は`#study-mode-section`が存在する
  - `init`受理後は`#study-mode-section`が取り除かれる
  - `init`受理後もテーマ設定のラジオボタン（2件）は残る
- 既存Jestテストスイート（107件、全て合格）

## 結果

BhvVisualizerから開いた学習者の設定パネルにはテーマ切り替えだけが表示され、学習者の操作で
`marker`イベントが送られることはなくなった。
