# ADR-042: ヒートマップ・実行トレースで1つの文の実行を1回・1行として扱う

## ステータス

採択済み（2026-10-05）

## コンテキスト

「ソフトウェア基礎論」の教材を確認していたところ、2つの表示の不具合が見つかった。

1. **ヒートマップ**: `sum += count;` の行の実行回数が、実際の2倍になる（6回実行される行が「12回」と表示される）
2. **実行トレース**: 次のコードで、`console.log('A', i);` などの行が2回ずつ並ぶ。`i++;` の行も2回ずつ並ぶ

```js
let i = 1;
while (i <= 3) {
  console.log('A', i); // 文A
  if (i % 2 === 0) {
    console.log('B', i); // 文B
  }
  console.log('C', i); // 文C
  i++;
}
```

### なぜ起きたか

どちらのビューも「humanStep 1つ ＝ 行の実行1回（表の1行）」とみなしていた。しかし、[ADR-008](ADR-008-humanstep-definition.md) の humanStep の定義では、1つの文が複数の humanStep を持つことがある。

| 文 | humanStep |
|---|---|
| `console.log('A', i);` | ExpressionStatement の enter、CallExpression の exit |
| `i++;` | ExpressionStatement の enter、UpdateExpression の exit |
| `sum += count;` | ExpressionStatement の enter、AssignmentExpression の exit |
| `return n * f(n - 1);` | CallExpression の exit、ReturnStatement の exit |

ADR-008 は、ExpressionStatement を enter で止め（文の開始を見せる）、代入・インクリメント・関数呼び出しを exit で止める（値が確定した後を見せる）と定めている。このため、式文の多くは「開始」と「値の確定」の2つの humanStep を持つ。ステップ実行の停止点としては意図どおりの定義だが、各ビューはこれを「行の実行の回数」として数えたり、表の行として並べたりしていた。

`let i = 1;` のような変数宣言は exit だけで止まるため1回で済む。このため問題は式文（代入・インクリメント・関数呼び出しの文）だけに現れ、気づきにくかった。

## なぜ修正するか

- **課題の答えと食い違う**: 授業の課題には「この行は何回実行されるか」（行の実行回数）や「どの順に実行されるか」（実行順）を問うものがある。学習者はヒートマップや実行トレースで自分の答えを確かめる。表示が2倍になったり、同じ行が2回並んだりすると、正しく考えた学習者が自分の答えを疑ってしまう。
- **手で書くトレース表と形がそろわない**: 授業で手書きするトレース表は「1文1行、値は文の実行後」の形をしている。実行トレースが同じ文を「実行前」「実行後」の2行で示すと、手書きの表と見比べにくい。たとえば `i++;` の1行目には増える前の値が出るため、「`i++` を実行したのに `i` が変わっていない」と誤解させるおそれがある。
- **ビューによって数え方が違う**: ヒートマップと実行トレースが、同じ「行の実行」を別々の単位で示すのは一貫しない。

## 決定

humanStep の定義（ADR-008）は変えない。ビューの側で「文の実行」という単位に humanStep をまとめる。

humanStep はステップ実行の停止点やスライダーの位置など、ほかのビューやボタンでも使っている。定義そのものを変えると影響が広い。「行の実行を何と数えるか」は表示の問題なので、それを表示するビューの側で解決する。

### `src/utils/line-exec.js`（新規。Heatmap・ExecTrace で共有）

- `buildLineExecOwners(trace, humanSteps)`: 各 humanStep を「行の実行1回」に対応づける。humanStep を囲む文のうち、同じ行・同じ callDepth にある、ループ以外の最も外側の文を単位とする。同じ文の実行に属する humanStep は、最初の1つ（代表）に寄せる。while/do-while/for の条件式・更新式は、イテレーションごとに1回と数える。Program enter はどの行の実行にも数えない。最初はヒートマップの修正（commit `6facb1d`）で `heatmap/index.js` に置いたが、実行トレースでも使うためここへ移した。
- `buildExecRows(trace, humanSteps)`: 実行トレースの表の行を作る。代表が同じで、**連続している** humanStep を1行にまとめる。

### ヒートマップ

実行回数・ドット・連結線を、humanStep ごとではなく代表 humanStep ごとに数える（commit `6facb1d`）。

### 実行トレース

- 1つの文の実行を1行にする。行番号はまとめた最初の humanStep のもの、変数の値は最後の humanStep 時点（文の実行後）のものを表示する。
- 条件式列には、まとめた humanStep のどれかが条件の評価を含むときにその値を表示する。
- 文の途中で関数の中に入る場合（`console.log(sq(3));` など）は、関数の中の humanStep が間に入り、連続しなくなる。この場合は「呼び出し前」と「戻った後」の2行に分ける。表を上から読めば実行の順になるようにするためである。
- Program enter の行は出さない。変数が空の先頭行が、最初の文と同じ行番号で重なって見えていたためである。カーソルが Program enter にあるときは、どの行も強調しない。

## 結果・影響

- 上のコードの実行トレースは、29行（Program enter の行を含む）から18行（1文1行）になった。ヒートマップの回数は、実際に文が実行された回数と一致する。
- 「1ステップ進む」で、実行トレースの強調が1行ずつ下に移る。
- ユニットテストは `tests/utils/line-exec.test.js`（旧 `tests/views/heatmap.test.js`）にまとめた。
- 実行トレースの行数が変わるため、マニュアルのスクリーンショット（JSVisualizer の `web/manual*.html`、BhvVisualizer の学生向けマニュアル）は撮り直しが必要になる。
- ほかのビューで humanStep を「行の実行」として数えたり並べたりするものを今後追加するときは、`src/utils/line-exec.js` を使う。
